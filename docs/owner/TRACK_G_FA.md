# مسیر G: رشد و فروش (راهنمای اجرای شخصی مالک)

وضعیت: ۱۲ اکتبر ۲۰۲۶. منبع‌ها: `docs/ux/UX_AUDIT_2026-10-11.md` (P1-8، P2-2، P2-4، P2-5، P2-6)، `docs/STRATEGY_GAP_2026-10-12.md` (G4، G5، G8، U5، U8، اقدام شماره ۹)، کد `smartjudge_module.py` (مسیر `/lawyers/pilot-onboarding`)، `docs/legal/LAWYER_REVIEW_GATE_FA.md`.

## ۱. هدف
پنج کار که تبدیل بازدیدکننده به مشتری پولی را قابل‌اندازه‌گیری و قابل‌اعتماد می‌کند: (۱) بدانیم کاربر در کدام مرحله می‌ریزد (بدون ثبت متن پرسش یا شماره)؛ (۲) برنامه‌ی وکلا بدون سوءاستفاده؛ (۳) صفحات حریم خصوصی و شرایط مطابق واقعیت؛ (۴) راه ارتباط با پشتیبانی غیر از تماس تلفنی؛ (۵) نصب سایت روی گوشی (PWA).

## ۲. چرا الان
- بدون آمار قیف نمی‌دانیم کدام تغییر UX جواب داده؛ دسته‌ی P0 تغییرات UX ادغام شده و اثرش اندازه‌گیری نشده.
- مسیر `/lawyers/pilot-onboarding` در کد **بدون هیچ بررسی** پاسخ «تأییدشده، VIP یک‌ماهه» برمی‌گرداند (تأیید جعلی). این یک ریسک اعتباری است.
- صفحه‌ی حریم خصوصی می‌گوید داده با شخص ثالث به اشتراک گذاشته نمی‌شود، در حالی که پرسش‌ها برای مدل‌های زبانی و پیامک و پرداخت به ارائه‌دهنده‌ها می‌رود.
- پشتیبانی فعلاً فقط یک شماره تلفن است.

## ۳. پیش‌نیازها
- دسترسی مالک به کد از طریق issue (کدنویسی با agentهاست)؛ شما تصمیم‌گیر و بازبین هستید.
- **وکیل شما** برای: متن حریم/شرایط (G3) و ضوابط برنامه‌ی وکلا (G2). این دو بدون وکیل نهایی نمی‌شوند.
- برای G4: یک شماره‌ی کسب‌وکار (ترجیحاً جدا از شماره‌ی شخصی) و ساعت پاسخ‌گویی مشخص.
- برای G5: لوگوی مربع ۵۱۲×۵۱۲ پیکسل (PNG) و رنگ برند.

## ۴. قدم‌به‌قدم

### G1. آمار قیف بدون نقض حریم (پیشنهاد: جدول رویداد خودمان، نه Umami/Plausible)
مقایسه‌ی کوتاه:

| گزینه | مزیت | عیب برای ما |
|---|---|---|
| جدول رویداد خودمان (`analytics_events`) | هیچ سرویس/پورت/اسکریپت خارجی نمی‌خواهد؛ فقط اسم رویداد از فهرست مجاز + شناسه‌ی تصادفی نشست؛ بدون IP، متن، شماره؛ از دامنه‌ی خودمان می‌آید و فیلتر نمی‌شود | یک آخر هفته کار agent؛ داشبورد زیبا ندارد (گزارش متنی روزانه در ایمیل موجود) |
| Umami (خودمیزبان) | MIT، بدون cookie، قیف و رویداد سفارشی دارد، فقط به Postgres نیاز دارد | یک سرویس جدید روی سروری که ۹۶٪ دیسکش پر است؛ پورت پیش‌فرض ۳۰۰۰ با NestJS ما (پورت رزرو) تداخل دارد؛ ورود پیش‌فرض admin/umami باید فوراً عوض شود؛ آی‌پی را برای ساخت شناسه‌ی روزانه می‌بیند |
| Plausible (Community Edition) | سبک و ساده | نسخه‌ی خودمیزبان **قیف (funnels) ندارد** و فقط دو بار در سال به‌روز می‌شود؛ ClickHouse می‌خواهد (سنگین) |

توصیه: **جدول خودمان**؛ دلیل: قیف دقیقاً چیزی است که Plausible CE ندارد، Umami سرویس اضافه روی سرور تنگ است، و داده‌ی ما هیچ‌وقت از دامنه‌ی خودمان بیرون نمی‌رود. اگر بعد از ۳ ماه داشبورد تصویری لازم شد، Umami را روی سرور جدید (مسیر D) با پورت غیررزرو امتحان می‌کنیم.
۱) فهرست رویدادها را تأیید کنید (از گزارش شکاف): `first_message`، `login_started`، `login_done`، `draft_started`، `draft_done`، `lock_card_seen`، `checkout_started`، `paid`. چیز دیگری نخواهید؛ هر رویداد اضافه یک ریسک حریم است.
۲) issue بسازید:
```bash
gh issue create --repo Mahan-film/roxira-platform --title "analytics: privacy-preserving funnel events endpoint + daily report" --body "POST /api/v1/apps/judge/events accepting ONLY allowlisted event names (first_message, login_started, login_done, draft_started, draft_done, lock_card_seen, checkout_started, paid) plus a random per-session id and optional plan. No text, phone, IP or user agent stored. Rate limited. Table analytics_events(id, ts, session_id, event, plan) with idempotent DDL like payment_orders (schema change: owner reviews). scripts/ops/funnel_report.py prints daily counts into the existing daily email. See docs/STRATEGY_GAP_2026-10-12.md action 9."
```
۳) وقتی PR آمد: فقط جدول و فهرست رویدادها را بخوانید (ستون IP/متن نباشد). بعد از دیپلوی، خودتان یک نشست بسازید و ببینید در ایمیل روزانه شمارش آمد.
۴) هر هفته قیف را بخوانید: first_message → login_done → lock_card_seen → checkout_started → paid. بزرگ‌ترین ریزش را یادداشت کنید؛ همان محل اولین تغییر بعدی UX است.

### G2. برنامه‌ی وکلا با راستی‌آزمایی پروانه (نیازمند وکیل)
مشکل: کد کنونی هر درخواستی را «APPROVED» می‌کند. ابتدا خطر را ببندید، بعد درست بسازید.
۱) **همین هفته:** issue فوری برای غیرفعال‌کردن:
```bash
gh issue create --repo Mahan-film/roxira-platform --title "lawyers: disable fake auto-approval in /lawyers/pilot-onboarding" --body "pilot_lawyer_onboarding in smartjudge_module.py returns APPROVED / license_verified:true / VIP gift for any payload. Return 503 (or remove route) and hide /lawyers page until a verification queue exists. No VIP is granted without manual approval. Add a test."
```
۲) طراحی درست (تصمیم شما + وکیل): وکیل فرم پر می‌کند (نام، شماره‌ی پروانه، کانون/مرکز، شماره‌ی موبایل ورود)؛ وضعیت می‌شود «در انتظار»؛ **شما دستی** استعلام می‌کنید و تأیید یا رد می‌کنید؛ فقط بعد از تأیید اشتراک آزمایشی فعال می‌شود؛ هر تأیید در لاگ ثبت می‌شود.
۳) استعلام پروانه: از سامانه‌ی رسمی استعلام وضعیت وکیل در درگاه خدمات الکترونیک قضایی (adliran.ir) یا سایت رسمی مرکز وکلای قوه قضاییه / کانون وکلا استفاده کنید. نشانی دقیق و روش کار را خودتان روی سایت رسمی تأیید کنید؛ ما فقط از منابع ثانویه می‌دانیم که جست‌وجو با شماره‌ی پروانه یا شماره‌ی ملی ممکن است. حتماً از وکیل خودتان بپرسید کدام مرجع برای وکلای پایه‌ی یک، کارآموز و مشاور رسمی است.
۴) **از وکیل بپرسید (سؤال سخت):** (الف) آیا دادن اشتراک رایگان به وکیل در ازای «ارزیابی» محدودیت تبلیغاتی/تعرفه دارد؟ (ب) متن شرایط برنامه: مسئولیت خروجی با وکیل است، نه ابزار؛ (ج) مدت ذخیره‌ی شماره‌ی پروانه.
۵) پس از آن، issue کامل «صف تأیید + پنل ساده‌ی ادمین» به agent بدهید.

### G3. بازنویسی حریم خصوصی و شرایط (نیازمند وکیل)
۱) جدول واقعیت جریان داده را از کد/اسناد پر کنید (این فهرست درست و قابل‌تأیید است؛ اگر مورد دیگری هست اضافه کنید):

| داده | کجا می‌رود | نگهداری |
|---|---|---|
| متن پرسش و پاسخ | ارائه‌دهنده‌های مدل زبانی از مسیر OpenRouter (مثل DeepSeek/Google/Mistral) | مدل‌های `:free` هرگز داده‌ی پرونده نمی‌گیرند؛ درخواست حساس با `data_collection=deny` |
| فایل پرونده | تحلیل متن (و OCR با مدل بینایی) | متن ۷ روز (`CASEFILE_RETENTION_DAYS`) |
| شماره موبایل / OTP | سرویس پیامک (Kavenegar، SMS.ir) | تا پایان حساب |
| پرداخت | درگاه زیبال | رکورد سفارش در پایگاه‌داده |
| ترافیک وب | Cloudflare (پروکسی) | طبق خود Cloudflare |
| آمار قیف (G1) | فقط خودمان | بدون شناسه‌ی شخصی |

۲) ساختار پیشنهادی صفحه (برای وکیل): خلاصه‌ی ۵ خطی ساده در بالا («چه چیزی ذخیره می‌شود، برای چه کسی فرستاده می‌شود، چقدر می‌ماند، چطور حذف کنم، با چه کسی تماس بگیرم»)، سپس متن کامل.
۳) فهرست ادعاهای نادرست را حذف کنید: «به هیچ شخص ثالثی داده نمی‌دهیم»، «GDPR»، «صفر توهم»، «۱۰۰٪ ارجاع صحیح» (مرجع: بخش اعتماد و متن‌ها در `docs/ux/UX_AUDIT_2026-10-11.md`).
۴) نسخه‌ی پیش‌نویس را با یک issue از agent بگیرید (متن فارسی دقیقاً از جدول بالا) و **قبل از انتشار برای وکیل بفرستید**. دو سؤال برای وکیل: حذف داده‌ی کاربر به درخواست (قالب و مهلت)، و ثبت نشانی و نام شخصیت حقوقی در صفحه.
۵) تا امضای وکیل، فقط جمله‌ی «ادعاهای نادرست» حذف شود؛ بازنویسی کامل منتشر نشود.

### G4. کانال‌های پشتیبانی (واتساپ، بله، تلگرام، ایتا)
وضعیت دسترسی در ایران ۲۰۲۶ را من تأیید نکردم (منابع ۲۰۲۴–۲۰۲۵: واتساپ رفع فیلتر شد؛ تلگرام نامطمئن؛ بله و ایتا داخلی‌اند). پس **خودتان روی گوشی** با و بدون VPN تست کنید.
۱) ترتیب پیشنهادی: بله (کار می‌کند حتی در اینترنت ملی) + واتساپ Business؛ بعد تلگرام برای کاربران خارج؛ ایتا اختیاری.
۲) برای هر کدام یک حساب/کانال با نام «قاضی هوشمند – پشتیبانی» بسازید، توضیح پروفایل: ساعت پاسخ (مثلاً ۹ تا ۱۸) و «در پیام شماره‌ی ملی/پرونده نفرستید».
۳) لینک مستقیم هر کانال را بردارید (قالب‌ها: `https://ble.ir/<نام>`، `https://wa.me/<شماره بین‌المللی>`، `https://t.me/<نام>`، `https://eitaa.com/<نام>` – قبل از استفاده هر لینک را در مرورگر بزنید).
۴) issue برای اضافه‌شدن به صفحه‌ی `/contact` (فایل `app/support/page.tsx`):
```bash
gh issue create --repo Mahan-film/roxira-platform --title "support: add Bale/WhatsApp/Telegram links and response hours to /contact" --body "Add link buttons (links provided in a comment by the owner), stated response hours, and a note not to send national id or case numbers over chat. No tracking scripts, plain links with rel=noopener."
```
لینک‌ها را در همان issue کامنت کنید.
۵) تست: پیام آزمایشی از شماره‌ی دیگر بفرستید؛ زمان پاسخ را بسنجید و در صفحه همان را بنویسید.

### G5. نصب سایت روی گوشی (PWA)
مستند Next.js: PWA فقط به manifest معتبر و HTTPS نیاز دارد؛ فعلاً `manifest` در برنامه نیست.
۱) لوگو را آماده کنید: `icon-192x192.png` و `icon-512x512.png` (می‌توانید از https://realfavicongenerator.net بسازید).
۲) issue:
```bash
gh issue create --repo Mahan-film/roxira-platform --title "pwa: add app/manifest.ts and icons for ghazihoushmand.ir" --body "Add app/manifest.ts (name, short_name, start_url /chat, display standalone, lang fa, dir rtl, theme/background colors, 192 and 512 icons incl. maskable) per Next.js PWA guide. No push notifications and no service worker in v1. Verify installability with Lighthouse."
```
۳) آیکن‌ها را کنار issue بفرستید یا در پوشه‌ی `public/` بگذارید.
۴) بعد از دیپلوی تست: روی اندروید Chrome > منو > Install app؛ روی iPhone Safari > Share > Add to Home Screen. انتظار: آیکن روی صفحه‌ی اصلی و باز شدن بدون نوار مرورگر. برای تست رسمی: Chrome DevTools > Lighthouse > Progressive Web App.
۵) حالت کم‌حجم و آفلاین را بعد از چند هفته آمار قیف (G1) تصمیم بگیرید.

## ۵. چطور بفهمم درست انجام شد
- [ ] G1: ایمیل روزانه شمارش هر مرحله‌ی قیف را دارد؛ جدول هیچ ستون IP/متن ندارد.
- [ ] G2: مسیر قدیمی دیگر «APPROVED» ساختگی نمی‌دهد؛ یک تأیید تستی دستی در لاگ ثبت می‌شود؛ پاسخ وکیل ثبت شده.
- [ ] G3: جدول جریان داده با واقعیت می‌خواند؛ ادعای «هیچ شخص ثالث» نیست؛ امضای وکیل ثبت شده.
- [ ] G4: لینک‌ها کار می‌کنند و زمان پاسخ نوشته شده؛ یک پیام آزمایشی جواب گرفت.
- [ ] G5: نصب روی یک اندروید و یک آیفون موفق است.

## ۶. خطرها و راه برگشت
- جدول رویداد اگر اشتباهاً متن بگیرد نقض حریم است: بازبینی PR توسط شما اجباری است؛ برگشت = حذف مسیر و `DROP TABLE` از طریق PR بازبینی‌شده (مهاجرت مستقیم روی تولید ممنوع).
- بستن برنامه‌ی وکلا ممکن است یک وکیل آزمایشی را ناراضی کند: پیام کوتاه «در حال بازطراحی» کافی است.
- متن حقوقی بدون وکیل منتشر نکنید.
- کانال پشتیبانی تعهد زمانی می‌سازد: ساعت واقعی بنویسید.
- PWA: اگر نصب مشکل ساخت، حذف `manifest.ts` برگشت کامل است.

## ۷. زمان و هزینه
G1 ۳۰ دقیقه شما + کار agent؛ G2 ۳۰ دقیقه + پاسخ وکیل؛ G3 یک ساعت شما + ساعت‌های وکیل (هزینه‌ی مشاوره)؛ G4 یک ساعت؛ G5 ۲۰ دقیقه + عکس لوگو. هزینه‌ی ابزار: صفر (Umami/Plausible لازم نیست).

## ۸. کجا Claude کمک می‌کند
- متن issueها و بازبینی PR (به‌ویژه فهرست ستون‌های جدول رویداد).
- پیش‌نویس فارسی ساده‌ی حریم/شرایط و سؤال‌های آماده برای وکیل؛ ارسال به شما، نه انتشار.
- خروجی ایمیل روزانه‌ی قیف (فقط عددها) برای تحلیل ریزش.
- اگر نصب PWA یا لینک کانال مشکل داشت: اسکرین‌شات خطا/نتیجه‌ی Lighthouse.
