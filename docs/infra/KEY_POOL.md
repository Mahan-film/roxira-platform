# LLM key pool (free-first gateway)

One OpenAI-compatible endpoint for every agent and project. Single source: `config/key_pool.yaml`.
Model ids come from `config/models.yaml` (role/alias refs); provider-native ids not in that registry are
listed in `key_pool.yaml` and marked unverified.

## How it works
- Groups (the "model" name you send): `agent-free` and `private`.
  - `agent-free`: code/docs/dev only. Order: Groq (every set key, shuffled) -> SambaNova -> Mistral
    -> Gemini Flash -> OpenRouter `:free` -> OpenRouter paid DeepSeek Flash (last resort).
  - `private`: customer/case data. Only `no_train` paid providers (today: OpenRouter DeepSeek with
    `data_collection=deny`). The renderer and client refuse to build it if a free or `may_log` provider gets in.
    It uses only `OPENROUTER_API_KEY` (the prod key), never `OPENROUTER_API_KEY_AGENTS`, whose workspace allows data-training endpoints.
    Never send customer data to `agent-free`.
- Gateway: LiteLLM proxy in docker on `127.0.0.1:4000` (never public). Config is generated by
  `scripts/infra/key_pool/render_litellm.py`: per-key rpm/tpm, `order` = provider priority, simple-shuffle among
  equal order (the Groq keys), 429 cooldown 60 s, retries 3. Providers whose key is not set are left out.
- No gateway (Mac): `scripts/dev/llm.sh "prompt"` / `scripts/dev/llm_pool.py` call providers directly in the same
  order, rotate on 429/5xx/timeout, and cool a failing provider down (OpenRouter from Iran without VPN is skipped
  after one 5 s TCP check). Keys are read from the environment or `~/Secrets/roxira/roxira.env`, never printed.
- `run_task.sh --gateway --public` makes OpenCode use `keypool/agent-free` (URL from `AGENT_GATEWAY_URL`,
  key `KEYPOOL_MASTER_KEY`). Default stays direct Groq.

## Owner commands
```bash
# missing keys on the server (hidden prompt, or --from-local to copy from the Mac)
bash scripts/ops/set_server_env.sh SAMBANOVA_API_KEY
bash scripts/ops/set_server_env.sh MISTRAL_API_KEY
bash scripts/ops/set_server_env.sh KEYPOOL_MASTER_KEY --generate   # gateway password (required)
# on the server, in the repo checkout
bash scripts/infra/key_pool/install.sh            # dry-run: shows key NAMES found, port check, image
bash scripts/infra/key_pool/install.sh --apply    # writes generated/, pulls image, compose up
bash scripts/infra/key_pool/health.sh             # ok / 429 / fail per provider and per group
```
`install.sh` refuses if port 4000 is busy. `--apply` writes the config, brings the stack up and, if the
`roxira_keypool` container already exists, restarts it so the changed config is loaded. The image tag in
`gateway.image` is unverified: if `docker pull` fails, fix the tag in `key_pool.yaml` and re-run.

## Virtual keys and the Mac/laptop tunnel (#430, owner 2026-11-05)
- The gateway has its own Postgres container `roxira_keypool_db` (no published port, own volume, 256 MB cap) for LiteLLM's
  key/spend tables only. `install.sh --apply` creates `generated/keypool-db.pass` and `generated/litellm.salt` once (mode 600).
  The master key still works if the DB is down (`allow_requests_on_db_unavailable`), so the product runtime is unaffected.
- `python3 scripts/infra/key_pool/virtual_keys.py` creates `gateway.virtual_keys` (`mac-agents` 3 USD/day, `laptop-mahansudo-srv`
  2 USD/day, paid spend only) and writes the values to `generated/virtual-keys.env` (never printed). `--rotate <alias>` re-creates one.
- The agents on the Mac and the laptop reach `127.0.0.1:4000` on srv1 through an ssh tunnel (local port 4181):
  docs/ops/TWO_COMPUTERS.md. Mistral keys sit at 402 today: they stay in the chain with a 30-minute cooldown. 400/403 count as
  a failed key (`allowed_fails_policy`), so a region/IP block moves traffic to the next key at once.

## Cost and latency log
- `gateway.cost_log: true` makes the renderer add the LiteLLM callback
  `cost_logger.proxy_handler_instance`; the proxy writes one privacy-safe JSON line per call to
  `/logs/requests.jsonl` (host: `/var/log/roxira-keypool/requests.jsonl`, rotated to `.1` past 200 MB).
  Only counts, cost, latency and model ids are logged: never prompts, responses, keys or user ids.
- Report: `python3 scripts/infra/key_pool/cost_report.py [--today|--days N] [--short]` prints calls,
  success %, total cost, cost per successful call and p50/p95 latency per group, plus the top 5
  deployments by cost. `--short` is capped at 12 lines for the owner's bot.
- After merging a change to this file or `cost_logger.py`, run on the server:
  `bash scripts/infra/key_pool/install.sh --apply`.

## Every key, every provider (owner decision 2026-10-22)
- Each provider has 4 key slots: `NAME`, `NAME_2`, `NAME_3`, `NAME_4`. Unset slots are skipped at render, so a
  provider with no key set is inert. Providers: Groq, SambaNova, Mistral, Gemini, OpenRouter (agents and product
  workspaces), NVIDIA NIM, Cloudflare Workers AI, DeepSeek, Chutes, Together, Fireworks.
- Load sharing: in a ladder rank every key of every provider that serves that model is one LiteLLM deployment of
  the same group, picked by weighted simple-shuffle (weight = the key's rpm, or `weight`). A 429/error cools that
  deployment for 60 s; when the whole rank fails the router moves to the next rank, and the ladder ends as before.
- Per-key limits (the owner sets them): under the provider,
  `limits_per_key: {GROQ_API_KEY_4: {rpm: 60, tpm: 12000, weight: 60}}`, merged over `limits`.
- OpenRouter: `OPENROUTER_API_KEY*` = product workspace (data training off; the only keys `private` uses),
  `OPENROUTER_API_KEY_AGENTS*` = agents workspace. `:free` models use all of them; paid agent steps use the agents
  keys (the product key only if no agents key is set).
- Inventory: `python3 scripts/infra/key_pool/inventory.py [--env-file /opt/roxira_platform/.env]` lists every slot
  per provider as set/unset (names only). `--probe` sends one 1-token call per set key (paid providers: ~1 token).

## Add a key or provider
- Extra key for an existing provider: put it in the next free slot with
  `bash scripts/ops/set_server_env.sh GROQ_API_KEY_4` (docs/ops/ADD_LLM_KEY.md), check it with
  `inventory.py --probe --provider groq`, then `bash scripts/infra/key_pool/install.sh --apply`.
- New provider: add a block under `providers:` (tier, data_policy, base_url, litellm_prefix, 4 key slots, models,
  limits), list it in the groups/ranks that serve its models. Mark `may_log` unless you have read the terms. A URL
  that needs a non-secret setting uses `{NAME}` plus `env_vars: [NAME]` (Cloudflare account id). Run
  `python3 -m pytest scripts/infra/key_pool/tests` (never over `src/`).

## Graduating a new provider to the product groups
New providers (NVIDIA NIM, Cloudflare Workers AI, DeepSeek direct, Chutes, Together, Fireworks) are
unverified. Until they graduate they sit only in the agent/builder groups (`agent-*`, `best-all`, `agent-free-paid`)
and in the `candidates` group; they must NOT be listed in `product-free`, `best-product*`, `vip-*`,
`summarize-cheap` or `private`, and no customer-facing group may fall back to `candidates`.
To graduate one: (1) `inventory.py --probe --provider <name>` returns ok for every model id it serves, (2) it wins
or ties in a bake-off against the current product ladder (clean `content`, no leaked reasoning, latency under the
chat first-token budget), (3) its terms are read and `data_policy` is set honestly (DeepSeek direct stays out of
`vip-product` and `private` unless it is `no_train`). Then add it to the product group in `config/key_pool.yaml`
and update `test_unverified_providers_stay_out_of_customer_facing_groups`.

## Reuse in a NEW project
```bash
export OPENAI_BASE_URL=http://127.0.0.1:4000/v1     # on the server; from elsewhere use an ssh tunnel
export OPENAI_API_KEY=$KEYPOOL_MASTER_KEY
# model = group name: "agent-free" for dev work, "private" for customer data
```
Any OpenAI SDK works unchanged. Without the gateway copy `llm_pool.py`/`key_pool.yaml` or call `llm.sh`.

## Upgrading the LiteLLM image

`python3 scripts/infra/key_pool/upgrade.py` (run on srv1 from the repo checkout). Default = canary only: it
renders the current `config/key_pool.yaml`, starts the pinned `gateway.image` beside the live gateway on a free
loopback port (14010-14014), tests models list, chat, `/v1/embeddings` to TEI (single, batch, float, parity with the
live gateway), ladders and cost logging, prints a PASS/FAIL table and removes the canary. `--plan` changes nothing,
`--apply` switches `127.0.0.1:4000` only if the table is all PASS (backup in `generated/.rollback/`, automatic
rollback if the live smoke test fails), `--rollback` restores the newest backup by the old image ID. Disk guard:
refuses below 5.5 GB free before the pull and below 1.5 GB after it. The old image is never removed by the script.
