# VPN اضطراری روکسیرا (Xray + REALITY، چند مسیره)

## چیست؟
یک سرویس بدون پنل وب (headless): Xray-core روی سرور اصلی با کاربر بدون دسترسی (`xray-vpn`) و systemd سخت‌شده.
اسکریپت‌ها: `scripts/infra/vpn/`. به‌جای یک مسیر، سه مسیر مستقل داریم تا اگر یکی فیلتر شد، گوشی خودکار از بقیه استفاده کند:

| مسیر | چیست | پورت | وقتی کار می‌کند که… |
|---|---|---|---|
| ۱ | VLESS + Vision + REALITY (dest فعلی) | 8443 | فیلتر فقط روی SNI/رفتار باشد |
| ۲ | REALITY دوم، کلید و dest جدا (پیش‌فرض dl.google.com) | 9443 | مسیر ۱ با dest یا پورتش شناسایی شده باشد |
| ۳ | XHTTP پشت Cloudflare روی یک دامنهٔ خودمان | 443 (Cloudflare) | **IP یا پورت سرور** مسدود باشد ولی Cloudflare باز باشد |

نکته: مسیرهای ۱ و ۲ هر دو روی همان IP سرور هستند؛ اگر خود IP بسته شود فقط مسیر ۳ جواب می‌دهد.
علت قطع‌شدن‌های گاه‌به‌گاه هنوز اثبات نشده (سرور سالم بود)؛ احتمال قوی فیلترینگ روی یک IP و پورت است.
پورت‌ها طبق AGENTS.md §7 انتخاب شده‌اند (۹۴۴۳ و ۱۰۴۴۳ آزاد و رزرو نیستند؛ قبل از اجرا خود اسکریپت `ss` را چک می‌کند).

## دستورات مالک (روی سرور، به ترتیب)
همه‌ی اسکریپت‌ها پیش‌فرض dry-run هستند؛ بدون `--apply` چیزی تغییر نمی‌کند.
```bash
cd /opt/roxira_platform/scripts/infra/vpn
sudo ./add_paths.sh --xhttp-host vpn-cdn.roxira.net                 # فقط برنامه را نشان می‌دهد
sudo ./add_paths.sh --xhttp-host vpn-cdn.roxira.net --apply         # مسیر ۲ و ۳ را اضافه می‌کند
sudo ./health.sh                                                    # وضعیت هر مسیر
sudo ./subscription.sh phone                                        # مجموعه لینک (base64) برای وارد کردن در برنامه
```
قبل از `--apply` در Cloudflare: یک رکورد DNS برای `vpn-cdn.roxira.net` (یا هر زیردامنهٔ خودتان) به IP سرور بسازید با **ابر نارنجی (Proxied)**
و SSL/TLS را روی **Full** بگذارید. (مسیر ۳ از گواهی self-signed پیش‌فرض nginx استفاده می‌کند؛ برای Full (strict) متغیرهای
`XHTTP_CERT` و `XHTTP_KEY` را بدهید.) اسکریپت فایل `roxira-vpn-xhttp.conf` را در `/opt/roxira_platform/nginx/sandboxes/` می‌سازد،
`nginx -t` می‌زند و فقط در صورت موفقیت reload می‌کند؛ در غیر این صورت فایل را برمی‌دارد.

سایر دستورات:
```bash
sudo ./vpn_client.sh add NAME | remove NAME | list | link NAME     # کاربران (add همه‌ی مسیرها را چاپ می‌کند)
sudo ./rotate.sh --port 8444 --dest dl.google.com:443 --keys --apply   # تغییر مسیر ۱
sudo ./rotate.sh --port2 9444 --dest2 www.apple.com:443 --keys2 --apply # تغییر مسیر ۲
```
`rotate.sh` قبل از تغییر از وضعیت (کلیدها، تنظیمات، کانفیگ) پشتیبان می‌گیرد، تعارض پورت و فرمت `host:port` را چک می‌کند،
کانفیگ را با `xray run -test` می‌آزماید و اگر سرویس/پورت‌ها بعد از ری‌استارت بالا نیامدند، وضعیت قبلی را خودکار برمی‌گرداند.

لینک/ساب‌اسکریپشن مثل رمز عبور است: در لاگ، چت یا گیت نگذارید. فقط روی صفحه چاپ می‌شود.

## وارد کردن در گوشی و انتخاب خودکار بهترین مسیر
خروجی `subscription.sh NAME` یک متن base64 است. آن را کپی کنید و:
- **Hiddify:** Add profile ← Paste from clipboard. حالت Auto/URL-test را روشن بگذارید؛ برنامه خودش سریع‌ترین مسیر سالم را انتخاب می‌کند.
- **v2rayNG:** `+` ← Import config from clipboard (برای ساب‌اسکریپشن)، سپس «Test all configs» و انتخاب سریع‌ترین.
مسیر ۳ (XHTTP) به هستهٔ Xray در برنامه نیاز دارد؛ v2rayNG و v2rayN و نسخه‌های جدید Hiddify و Streisand دارند. اگر برنامه‌ای
مسیر ۳ را نشناخت، همان یک ردیف را نادیده بگیرد و دو مسیر دیگر کار می‌کنند. (روی گوشی خودتان آزموده نشده؛ بعد از نصب یک بار امتحان کنید.)
هر دستگاه یک کاربر جدا بگیرد تا جداگانه حذف شود.

## بررسی سلامت
`sudo ./health.sh` برای هر مسیر یک خط OK/FAIL می‌دهد (سرویس، پورت، اینکه گواهی dest نام SNI را پوشش می‌دهد (SAN یا wildcard)، و برای XHTTP پاسخ Xray روی loopback و `nginx -t`؛ مسیر مخفی هرگز به لاگ nginx نمی‌رسد).
فقط سمت سرور را می‌سنجد. برای دیدن اینکه کدام مسیر از ایران باز است، از یک دستگاه داخل ایران:
```bash
./health.sh --external IP_سرور --port 8443 --port2 9443 --cdn-host vpn-cdn.roxira.net
```

## به‌روزرسانی Xray (با بازگشت)
```bash
sudo ./update_xray.sh --version v25.X.Y --sha256 HASH_از_صفحه_ریلیز             # dry-run
sudo ./update_xray.sh --version v25.X.Y --sha256 HASH_از_صفحه_ریلیز --apply
sudo ./update_xray.sh --rollback --apply                                        # بازگشت دستی
```
ترتیب: دانلود ← بررسی sha256 ← تست کانفیگ فعلی با باینری جدید (اگر رد شود چیزی تغییر نمی‌کند) ← ذخیرهٔ باینری قدیمی در
`/etc/xray-vpn/prev` ← نصب و ری‌استارت ← اگر سرویس یا پورت ۱ بالا نیامد، خودکار به نسخهٔ قبل برمی‌گردد.
به‌جای `--sha256` می‌توان `--fetch-dgst` داد (فقط خرابی دانلود را می‌گیرد، نه دستکاری ریلیز).

## بازگشت به حالت قبل (فقط مسیر ۱)
```bash
sudo ./add_paths.sh --remove --apply
```
مسیر ۲ و ۳، قانون‌های ufw و vhost nginx را برمی‌دارد؛ کلیدها نگه داشته می‌شوند. از `settings.env` و `config.json` قبل از هر تغییر
نسخهٔ پشتیبان در `/etc/xray-vpn/backup/<زمان>/` ساخته می‌شود. رکورد DNS در Cloudflare را دستی حذف کنید.

## اگر مسیری مسدود شد
1. `./health.sh` (سمت سرور سالم است؟) و سپس `./health.sh --external ...` از داخل ایران.
2. مسیر ۱ یا ۲ شناسایی شده: `rotate.sh` با dest/پورت دیگر. dest باید سایت بزرگ با TLS 1.3 و h2 باشد
   (`openssl s_client -connect X:443 -tls1_3 -alpn h2`).
3. IP مسدود شد: فقط مسیر ۳ می‌ماند؛ برای حل ریشه‌ای باید IP عوض شود (خارج از این اسکریپت).

## نکته شبکه
فایروال «فقط Cloudflare» روی 80/443 می‌ماند (مسیر ۳ از همان استفاده می‌کند). پورت‌های 8443 و 9443 برای همه باز است
(کامنت `roxira-vpn` در ufw). پورت XHTTP محلی (10443) فقط از شبکهٔ داکر (172.16.0.0/12) باز می‌شود، نه از اینترنت.
