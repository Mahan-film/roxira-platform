## ۲. زیرساخت

سرور تولید: `5.75.200.67` (Hetzner، اوبونتو، ۱۵ GB RAM، دیسک ۱۵۰ GB، ۸۱٪ پر، uptime ۶ روز، kernel reboot معوق). فقط پورت‌های 22/80/443 باز است.

۱۳ کانتینر: nginx (دروازه)، `roxira_app_prod` (هستهٔ AI با FastAPI)، frontend (Next.js، با `docker run` نه compose)، backend (NestJS)، Postgres 17 + PgBouncer، Redis، Qdrant، و سه کانتینر Twenty CRM و دو sandbox خودکار که در compose اصلی نیستند (ریسک drift).

داده: Postgres (`enterprise_db`)، Qdrant با ۸ کلکسیون (`iran_laws_v2` با ۵۱۰۳ نقطه است و برای پاسخ استفاده می‌شود؛ `judicial_precedents`، `judiciary_circulars`، `legal_advisory_opinions` و غیره وجود دارند ولی محتوا و استفادهٔ آن‌ها نامشخص است)، SQLite برای auth، Redis.

زمان‌بندی روی سرور: autodaemon هر ۳۰ دقیقه (فقط audit)، radar هر ۶ ساعت، خزندهٔ قانون ۰۳:۳۰، backup ساعتی، `daily_tech_scout` ساعت ۰۴:۳۰. بک‌آپ روزانه به Mac شما کشیده می‌شود.

دیسک: ۴۹ GB build cache و ۳۱ GB image بلااستفاده روی سرور قابل پاک‌سازی است؛ این بزرگ‌ترین بهبود ارزان است (نیاز به تأیید شما، چون نوشتن روی سرور است).

استقرار: `deploy-prod.yml` فعال است. بعد از سبز شدن کل CI روی `main`، با کلید SSH مقید به `ci-deploy.sh` استقرار می‌کند. کلید قطع‌کن: متغیر `DEPLOY_ENABLED` یا فایل `.deploy-freeze`. سرور الان روی کامیت #255 است.

## ۴. خط تولید ساخت خودکار (Factory) و auto-merge

جریان: بریف (issue با لیبل `brief`) → تحقیق چندزبانه → پیشنهاد فارسی → `/approve` شما → planner حداکثر ۱۵ issue کوچک می‌سازد → ایجنت‌های OpenCode روی runnerهای زودگذر GitHub PR می‌زنند → CI + بازبین از خانوادهٔ مدل دیگر → auto-merge فقط برای شاخه‌های `agent/*` و مسیرهای غیرحساس.

وضعیت: auto-merge روی مخزن روشن است (`AUTO_MERGE_ENABLED=true`)؛ هاب PRهای سبز را با `gh pr merge --auto --squash` ادغام می‌کند. تحقیق Factory روی بریف #236 چهار بار شکست خورد و علل (سقف `models`، خروجی خالی مدل رایگان، event loop بسته) رفع شد. اجرای فعلی سه بهبود گرفته: انتخاب لایه‌ها، موضوع = عنوان + هدف، و نرمال‌سازی گزینه‌ها با fallback توصیه‌شده (#255، که همان مشکل لایهٔ فرانت‌اند بدون نام را هدف می‌گیرد؛ اجرای بعدی باید همین را اثبات کند).

مسیر ساخت محلی: `rx <issue>` با Codex، بعد dsflash → dspro → codestral. سقف‌ها: ۳ rx، ۲ subagent، ۱ چت اضافی. هاب (Sonnet) کد محصول نمی‌نویسد.

## ۵. مسیر حقوقی (هستهٔ ارزش محصول)

- قوانین سرو‌شده: ۸ قانون، ۴٬۲۱۶ ردیف ماده، همه بدون `source_tier`.
- آماده ولی وارد نشده: `phase1_official_v2.jsonl` با ۱۵۰۴ ردیف از ۱۷ قانون رسمی (rc.majlis.ir). ورود به Qdrant تولید نیاز به «بله»ی صریح شما دارد (برنامه: بک‌آپ، کلکسیون جدا، تست نمونه، سپس سوییچ).
- قواعد وکیل: مواد منسوخ حذف شود؛ فقط منبع رسمی؛ نظر مشورتی معتبر نیست؛ رأی وحدت رویه معتبر است.
- شکاف‌ها: آرای وحدت رویه، سه قانون هم‌پوشان (آیین دادرسی مدنی، شوراهای حل اختلاف، چک)، اتصال `jurisdiction_rules.yaml` به پاسخ‌ها.

## ۶. هدف نهایی

سیستمی که برای هر پروژهٔ شما (و تغییرات قاضی هوشمند) تحقیق می‌کند، فارسی پیشنهاد می‌دهد، بعد از تأیید شما با ایجنت‌های ارزان می‌سازد، پیش‌نمایش و تست E2E می‌گیرد، استقرار و rollback می‌کند و گزارش فارسی می‌دهد، با سقف هزینهٔ روزانه و کلید قطع‌کن در هر مرحله.

بخش‌های باقی‌مانده طبق `FULL_AUTONOMY_GAP_ANALYSIS`: preview environment (مسدودکننده)، قالب‌های طلایی، ledger/بودجهٔ کل درخواست در workflowها، گزارش نهایی فارسی، مشاهده‌پذیری بعد از استقرار (Gatus)، و ساخت repo جدا برای پروژه‌ها.

## ۷. ارزیابی استراتژیک (نظر من، قابل بحث)

1. **درآمد و کیفیت حقوقی در اولویت اول بماند.** بخش بزرگ ۷۳۴ کامیت و کارهای اخیر زیرساخت ساخت خودکار است. ولی فقط قاضی هوشمند درآمد دارد و کیفیتش به پوشش ۸ قانون محدود است. ورود ۱۷ قانون رسمی آماده‌شده سریع‌ترین جهش کیفیت محصول است و کار اضافه نمی‌خواهد جز تأیید شما.
2. **تک‌سرور = تک نقطهٔ شکست.** پیش از preview روی همین سرور (۸۱٪ دیسک، حداکثر ۲ preview) اول پاک‌سازی ۴۹ GB build cache، reboot kernel و تست بازیابی بک‌آپ. یا preview را روی سرور جدا ببرید (Hetzner کوچک حدود ۵ یورو در ماه).
3. **کلیدها در تاریخچهٔ git هستند.** مخزن private است و کلیدهای قدیمی باطل شده‌اند، پس ریسک کنترل‌شده است؛ ولی هر نشت یا public‌کردن، همه چیز را برملا می‌کند.
4. **دو چیز کنترل ناقص دارند:** چک‌های الزامی ruleset (Undefined names و System inventory هنوز اضافه نشده‌اند) و کانتینرهای خارج از compose (Twenty، sandbox، frontend).
5. **هزینه:** الان تقریباً صفر ثابت است (سقف‌های روزانهٔ OpenRouter + اشتراک‌های ثابت). پیشنهاد SearXNG/ddgs هزینهٔ جست‌وجو را حذف می‌کند و ساده‌ترین برد بعدی است.
