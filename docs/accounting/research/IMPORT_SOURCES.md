# Import sources: Iranian accounting packages (research 2026-11-04)

Goal: know what customers can export from Sepidar, Hamkaran/Rahkaran, Mahak and Holoo, so `data_import`
can offer one-click presets. Rule: **never invent a format**. Everything not shown by a public source is
marked `unverified`.

## Bottom line

No vendor publishes the exact column headers of its Excel export. The headers live inside the product
(Sepidar and Mahak hand out blank template files from the UI; Holoo and Rahkaran export report grids). Public
pages only describe the *process* and a few field names. Therefore:

- The fixtures in `e2e/fixtures/import-presets/<package>/` are **synthetic and generic-shaped**, not copies of a
  real export. Only the header names listed as `verified` below come from a public source.
- To make a preset real, a licensed user must export the template files and attach them (issue opened for the
  laptop owner of `data_import`).
- Existing behaviour stays: ZIP of Excel/CSV + generic synonym matching + AI mapping (see `docs/IMPORT_SOURCE_PRODUCTS.md`).

## Sepidar (سپیدار — Sepidar Hamkaran System)

Exportable (all through the product's own "Send/Receive information" Excel templates, 2.x desktop):

| Entity | How | Notes |
|---|---|---|
| Counterparties (طرف حساب) | Company > counterparties list > select > Excel template > "ارسال اطلاعات"; import with "دریافت الگو" | Error `کد باید کوچکتر از 1000 باشد` when the numbering-method end of the detail code is below the Excel code |
| Goods/services (کالا/خدمت) | Goods list > multi-select > goods template > send | Unit names must exist beforehand and match spelling exactly (even parenthesis style); warehouse code must exist |
| Accounting documents (اسناد حسابداری) | Accounting > list > multi-select > "الگوی سند حسابداری" > send | Chart of accounts and detail accounts must exist in the target first; Gregorian dates appear unless Windows region/language is Persian |
| Sales invoice, warehouse receipt, inventory count, price notice, price list, fixed assets, bank statement, payroll monthly info | same pattern | Transfer-type warehouse receipts and personnel contracts cannot be imported; default sales template has no address field |
| Receipts (رسید دریافت) | "دریافت از اکسل" on the form | Bank and non-bank receipts both go through this form |

Encoding/format: Excel only. If the file is not shown in the import dialog, save as **Excel 97-2003 (.xls)**.
Leading/trailing spaces in warehouse codes break the import. Closed fiscal year blocks adding counterparties
with opening balances; opening-balance entry is only possible in the first year before the opening voucher.
Sepidar's own coding article describes five levels (group, kol, moein, tafsili 1, tafsili 2) and four default charts
(production, service, trading, contracting); the software tree itself is three levels.

Column headers: `unverified` (the template is generated by the UI). Verified field names: counterparty code, unit
name, warehouse code, and for bank statement: date, number, debit, credit (from the troubleshooting text).

Sources:
- https://sepidsystemtehran.com/excelsepidarsystem (Q&A with the per-entity procedures and error messages)
- https://www.sepidarsystem.com/courses/data-convert-in-sepidar (course page; users ask for sample formats, no answer)
- https://www.sepidarsystem.com/blog/accounting-coding (levels)
- https://hesabcenter.com/convert-data/ (third-party conversion service; Excel in, Sepidar and Dasht as targets only)
- https://www.sepidsystemtehran.ir/holootosepidar (Holoo to Sepidar via Excel: parties, goods, balances, vouchers)

## Hamkaran System Rahkaran (راهکاران)

Only one public item found: the trial balance report (Financial > General Ledger > Reports > تراز), with

## Mahak (محک)

Mahak's setup wizard offers "بانک اطلاعاتی خام + ورود اطلاعات پایه از فایل اکسل". The software supplies a
**sample Excel file** for **goods (کالاها)** and **persons (اشخاص)**; then you pick permanent (دائمی, default)
or periodic (ادواری) inventory accounting. Sheet names and headers: `unverified` (the page does not list them;
a video `vorood-az-excel.exe` is linked and was not downloaded). Mahak is store/warehouse oriented; no
vouchers or chart export was found.

Source: https://help.mahaksoft.com/2406/learn-how-to-import-basic-information-from-an-excel-file/

## Holoo (هلو)

- Reports can be saved as **Text, Excel or HTML** (invoice reports, "نمایش بصورت ستونی").
- Import side (verified field names shown when mapping Excel columns): `کد کالا`, `نام کالا`, `آخرین قیمت خرید`, `قیمت فروش`.
- Encoding quirks (verified): the letter ی may show unreadable after an import; replacing Persian ی with Arabic
  ي in Excel and re-importing fixes it. Holoo wants **.xls** (strip the trailing x from .xlsx names) and Latin file
  names. This means exports can contain Arabic ي/ك: normalise ي→ی and ك→ک on read.
- Four data classes people move out of Holoo: parties, goods/services, account balances, vouchers (via Excel);
  headers of those exports: `unverified`.

Sources: https://tabriztax.com/شیوه-انتقال-اطلاعات-از-اکسل-به-نرم-افزار/ ,
https://www.sepidsystemtehran.ir/holootosepidar

## Tax authority electronic ledgers (not a package, but a shared format)

The Darai electronic ledger system (سامانه دفاتر تجاری الکترونیکی) accepts Excel or CSV that must **exactly match
the downloadable template** (titles and order unchanged); dates `YYYY/MM/DD`; CSV needs a separator. Fields include
kol code and kol title. The full header list is in the downloadable template and is `unverified` here. Many
packages (Haseb Melli etc.) already export this template, so it is a good neutral input format to support.
Sources: https://www.ekhtebar.ir (user guide of the ledger system, via search snippet), https://hasebmelli.com/daraei-dafater/
