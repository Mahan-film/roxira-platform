## Operating model

- **OpenCode builds, Claude supervises.** 4 of 5 slots run OpenCode; Claude writes small, exact briefs, reads every diff, and writes code itself only after OpenCode fails the same task twice. Never trust a model's "all tests pass".
- **Models go through the srv1 gateway.** srv1 has a stable German IP, so Groq and Gemini work there.
  - Tunnel: `127.0.0.1:4181` → srv1 `127.0.0.1:4000`. Set up per `docs/ops/TWO_COMPUTERS.md`.
  - Key: `~/Secrets/roxira/llm-gateway.env` (`laptop-mahansudo-srv`, 2 USD/day on paid models).
  - Chain: free first (Groq, Gemini, OpenRouter `:free`, SambaNova, Cloudflare, Mistral), then DeepSeek V4.1 Flash. Use a strong model only after two failures.
  - Direct provider keys are the last fallback only.
- **Cost rules** (`fleet.py`, #455): a config or auth error on a free model stops the job and never falls through to a paid model. The paid cap is 2 USD/day. Never send real customer data to free models.
- **Merging:**
  - The laptop pushes at least every 30 min and runs `gh pr ready` when done. It never runs `gh pr merge`.
  - The Mac's hourly scheduled task `roxira-review-desk` reviews `mahansudo` PRs (cross-family, through the gateway) and enqueues PRs that have a real PASS, green CI, and no conflict.
  - An empty or timed-out review is **not** a pass.
- **Hotspots** (`package.json`, lockfiles, `app.module.ts`, `app-shell.tsx`, `permission-matrix.snapshot.json`, new migrations): one writer at a time, with `[hotspot]` in the PR title.
- **Deploy:** autodeploy from `main` every 5 min on srv1, with pg_dump, migrate, smoke test and GATE4 browser smoke, and automatic rollback. If prod HEAD stops moving, read `journalctl -u roxira-autodeploy`. That is read-only; ask the owner before changing srv1.
- **Mac fleet is paused** (`ir.roxira-fleet` booted out). Resume instructions are in the closing tally on #230.

## Adding the new Mistral keys (owner, on the Mac)

Each command asks for the key without showing it and appends it to srv1's `.env`. Then restart the gateway container so it picks the keys up.

```bash
read -rs -p "Mistral key 5: " K && printf 'MISTRAL_API_KEY_5=%s\n' "$K" | ssh roxira-prod 'cd /opt/roxira_platform && cp -p .env ~/env.bak.$(date +%s) && cat >> .env' && unset K && echo ok
```

```bash
read -rs -p "Mistral key 6: " K && printf 'MISTRAL_API_KEY_6=%s\n' "$K" | ssh roxira-prod 'cd /opt/roxira_platform && cat >> .env' && unset K && echo ok
```

Then a laptop agent adds `MISTRAL_API_KEY_5` and `MISTRAL_API_KEY_6` as deployments in the gateway config with a PR (same pattern as #433), and the keypool container is recreated.
