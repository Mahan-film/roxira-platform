## 3. Service: modules/inventory/purchasing/purchase-cycle.service.ts
Injectable; deps: TenantScope, PurchaseRepository, InventoryService, StockDocumentsService (for resolveAccounts), AccountingService. All methods take tenantId first, userId second where relevant. Throw Nest HttpExceptions: PurchaseDomainError -> 409 except UNKNOWN_ORDER_LINE/INVALID_LINE -> 400; not found -> 404 (never reveal other tenants' rows).
- createRequest(tenantId,userId,{lines:[{sku,quantity}]}) status OPEN; cancelRequest; listRequests.
- convertRequest(tenantId,userId,requestId,{supplierCode,warehouseId?,orderDate,prices:{[sku]:unitPrice}}) -> DRAFT order, request ORDERED + orderId. Every sku must have a price.
- createOrder(tenantId,userId,{supplierCode,warehouseId?,orderDate,lines:[{sku,quantity,unitPrice}]}) uses validateOrderLines; status DRAFT.
- approveOrder (DRAFT->APPROVED via assertTransition; sets approvedBy/At), cancelOrder (only before receipts), closeOrder (PARTIALLY_RECEIVED->CLOSED).
- createReceipt(tenantId,userId,orderId,{lines:[{orderLineId,quantity,weight?}],idempotencyKey?,receivedAt?}): ONE TenantScope.run transaction: if idempotencyKey exists for the tenant return the first receipt (status 200 semantics: same body). Lock the order FOR UPDATE, load settings, `planReceipt(order, lines, settings)`. For each line call InventoryService.receiveStock(tenantId, {sku, quantity: Number(q)/100, unitPurchaseCost: Number(unitCost)/100, warehouseId: order.warehouseId ?? undefined, receivedAt, reference: receiptNumber}, manager) and store result.layers[0].batchId as fifoBatchId (check its type). Insert receipt + lines, update the order's received quantities and statusAfter. Post the journal: `purchasePostingLines({kind:'GOODS_RECEIPT',...})`; resolve each role's account code with StockDocumentsService.resolveAccounts(tenantId, [resolvePurchaseRole(INVENTORY), resolvePurchaseRole(GRNI)]) (inside the same flow; if it uses its own connection that is OK, it only reads/creates accounts), then AccountingService.createJournalEntry(tenantId, {entryNumber:`GRN-${receipt.number}`, date, description, lines:[{accountCode, debit|credit as the string form of the rial amount (minor units/100 using money.ts helpers, no floats), partyCode for GRNI line}]}, manager). Save journal_entry_id on the receipt. Any failure rolls back stock and receipt together. Quantities in the API are strings of the bigint hundredths (e.g. "1000" = 10.00).
- getSettings / updateSettings (overReceiptToleranceBp 0..10000, priceToleranceBp, priceToleranceAbs as string bigint).
- Read endpoints: getOrder, listOrders(status?), getReceipt, listReceipts(orderId?).
bigint must never go through JSON.stringify: responses convert bigint to decimal strings.
