## 1. Pure replay: reports/stock-movements.ts (+ stock-movements.spec.ts)
Why: stock documents (erp_stock_documents / erp_stock_document_lines, see entities/stock-document.entity.ts) store a TRANSFER as one line with a blended unit cost, but the cores need a transfer-in leg that carries the cost of EACH layer the transfer-out consumed. So rebuild the movements by replaying FIFO.
```ts
export interface MovementDoc { id: number; docType: StockDocumentType; docDate: string /*YYYY-MM-DD*/; docNumber: string; fromWarehouseId: number|null; toWarehouseId: number|null;
  lines: Array<{ id: number; sku: string; quantity: number /*decimal units, signed for ADJUSTMENT*/; unitCost: number /*rial decimal*/ }> }
export function replayMovements(docs: readonly MovementDoc[]): BalanceMovement[]   // itemId = sku, warehouseId = String(id) | null
```
Convert once at the edge: qty hundredths = BigInt(Math.round(quantity * 100)); unit cost minor = toMinor(unitCost). Document label (CardexMovement.document) = docNumber.
Processing order (stable sort): docDate ascending; then rank: 0 = inbound (OPENING, PURCHASE_RECEIPT, and ADJUSTMENT lines with positive quantity), 1 = TRANSFER, 2 = outbound (SALES_DELIVERY and ADJUSTMENT lines with negative quantity); then doc id; then line id. (This is the "same-day movements inbound first" rule.)
Per sku keep one FIFO queue per warehouse key (null warehouse is its own key), layers {qty, unitCost, seq}; seq is assigned when a layer is created and a transferred layer KEEPS its seq (so FIFO order survives the move, like moveLayers in repositories/stock-documents.repository.ts).
- Inbound line: warehouse = toWarehouseId ?? fromWarehouseId; push layer; emit INBOUND {date, document, quantity, unitCost}.
- Outbound line (quantity = abs): warehouse = fromWarehouseId ?? toWarehouseId. If a warehouse is set consume only its queue oldest-seq first; if null, consume across ALL queues of that sku oldest seq first (this mirrors persistOutbound in repositories/inventory.repository.ts, which does not filter when warehouseId is null). Emit one OUTBOUND movement per consumed layer, with warehouseId = that layer's queue key. If the stock runs out, emit one more OUTBOUND for the remainder (warehouse = the document's warehouse or null) so cardex() reports a shortage.
- TRANSFER line: consume from fromWarehouseId's queue oldest first; for each consumed layer emit OUTBOUND {transfer:true, warehouse from, quantity take} and INBOUND {transfer:true, warehouse to, quantity take, unitCost: layer.unitCost} and push the layer (same seq, same unitCost) into the destination queue. A shortage on a transfer is emitted only as an OUTBOUND remainder (transfer:true).
The returned array is in processing order. Pure function, no I/O, bigint only, no floating arithmetic beyond the two edge conversions.
